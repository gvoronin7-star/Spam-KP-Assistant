#### P01 — GUI Настройка моделей LLM

**Проблема:** Сейчас настройка LLM требует редактирования `.env` файла. Пользователь не может выбрать модель в интерфейсе.

**Решение:** Диалог настройки с:
- Выпадающим списком доступных моделей (gpt-5.4-mini, gpt-5.3-chat, gemini-3.1-flash)
- Полем для API-ключа с маскированием
- Настройкой rate limiting (RPM, TPM)
- Кнопкой "🧪 Тестировать" — отправка тестового запроса
- Индикатором статуса подключения
- Сохранением настроек в БД (не в .env)

**Файлы:**
- `gui/dialog_llm_settings.py` — новый диалог
- `gui/main_window.py` — обновление кнопки "Настроить LLM"
- `core/models.py` — возможно, новая таблица настроек

**Критерии приёмки:**
- [ ] Пользователь может открыть диалог из "⚙️ Настройки"
- [ ] Можно выбрать модель из списка
- [ ] API-ключ сохраняется и маскируется
- [ ] Кнопка "Тестировать" показывает результат
- [ ] Настройки сохраняются между запусками

#### P05 — Тест подключения SMTP/IMAP

**Проблема:** Пользователь не знает, работают ли настройки почты, пока не попробует отправить/получить письмо.

**Решение:** Кнопка "🧪 Проверить подключение" в диалоге настройки SMTP:
- Проверка SMTP (отправка тестового письма себе)
- Проверка IMAP (подключение и чтение 1 письма)
- Вывод результата: ✅ Успешно / ❌ Ошибка с деталями

**Файлы:**
- `gui/dialog_smtp_settings.py` — добавить кнопку и логику

**Критерии приёмки:**
- [ ] Кнопка "Проверить" видна в диалоге SMTP
- [ ] При успехе — зелёное сообщение
- [ ] При ошибке — красное сообщение с деталями

#### P04 — Дашборд статистики LLM

**Проблема:** Нет прозрачности в расходах на LLM API. Пользователь не знает, сколько токенов потрачено.

**Решение:** Вкладка/диалог с метриками:
- Всего запросов к LLM (сегодня / неделя / месяц)
- Потрачено токенов (input / output)
- Примерная стоимость в рублях
- Среднее время ответа
- Количество ошибок
- График использования по дням

**Техническая реализация:**
- Новая таблица `llm_usage_log` (timestamp, model, tokens_in, tokens_out, cost, status)
- Логирование каждого запроса к LLM
- Агрегация данных для дашборда

**Файлы:**
- `core/models.py` — таблица `LLMUsageLog`
- `services/llm_service.py` — логирование
- `gui/dialog_llm_stats.py` — дашборд
- `gui/main_window.py` — кнопка доступа

**Критерии приёмки:**
- [ ] Каждый запрос к LLM логируется
- [ ] Дашборд показывает актуальную статистику
- [ ] Есть фильтр по периоду (день/неделя/месяц)
- [ ] Стоимость рассчитывается по прайсу моделей

#### P06 — Режим "Auto" для LLM-Агента

**Проблема:** Сейчас LLM-Агент работает только в режиме DRAFT (генерирует черновики). Пользователь должен вручную проверять и отправлять.

**Решение:** Режим полной автоматизации:
- **DRAFT** (как сейчас) — генерировать черновики
- **AUTO** (новый) — автоматически отправлять сгенерированные ответы
- **HYBRID** — отправлять автоматически, если уверенность LLM > 90%

**Безопасность:**
- В режиме AUTO создавать задачу "Проверить автоответ" для оператора
- Возможность отмены отправки в течение 5 минут
- Лог всех автоответов

**Файлы:**
- `gui/dialog_llm_agent.py` — добавить выбор режима
- `services/llm_agent_service.py` — логика автоотправки
- `core/models.py` — таблица `AutoReplyLog`

**Критерии приёмки:**
- [ ] Можно выбрать режим в диалоге LLM-Агента
- [ ] Режим сохраняется в БД
- [ ] AUTO режим действительно отправляет письма
- [ ] Создаётся задача на проверку
- [ ] Есть лог всех автоответов

#### P09 — Извлечение цен из КП

**Проблема:** Получив КП от поставщика, пользователь должен вручную извлекать цены, сроки, условия.

**Решение:** LLM-парсинг полученных КП:
- Загрузка файла КП (PDF, Word, Excel) или вставка текста
- LLM извлекает структурированные данные:
  - Название услуги
  - Цена (месяц / год / разово)
  - Валюта
  - Срок подключения
  - Условия оплаты
  - SLA / штрафы
  - Контакты для уточнения
- Сохранение в таблицу `kp_extracted_data`
- Автоматическое заполнение таблицы сравнения

**Техническая реализация:**
- Интеграция с `AttachmentParser` для извлечения текста из PDF/DOCX
- Промпт для LLM с few-shot примерами
- Валидация извлечённых данных

**Файлы:**
- `gui/dialog_kp_extractor.py` — диалог загрузки и извлечения
- `services/kp_extraction_service.py` — сервис извлечения
- `core/models.py` — таблица `KPExtractedData`
- `gui/dialog_kp_comparison.py` — обновление для автозаполнения

**Критерии приёмки:**
- [ ] Можно загрузить файл КП
- [ ] LLM извлекает цены и условия
- [ ] Данные сохраняются и отображаются в сравнении
- [ ] Точность извлечения > 80%

- Фильтр: Все / Активные / За период

**Файлы:**
- `gui/dialog_export.py` — диалог экспорта
- `services/export_service.py` — логика экспорта

**Критерии приёмки:**
- [ ] Можно выбрать тип данных
- [ ] Можно выбрать формат

#### P10 — Умное сравнение предложений

**Описание:** Автоматический расчёт лучшего предложения на основе извлечённых данных.

**Функционал:**
- Автозаполнение таблицы сравнения из извлечённых КП (P09)
- Расчёт "Лучшая цена" с учётом валюты и периода
- Расчёт "Лучший срок" подключения
- Расчёт "Лучший SLA" (гарантии)
- Сводная таблица: компания vs критерии
- Экспорт сравнения в Excel
- График цен (столбчатая диаграмма)

**Техническая реализация:**
- Нормализация цен (приведение к единому периоду)
- Весовые коэффициенты критериев (пользователь может настроить)
- Алгоритм ранжирования

**Файлы:**
- `services/kp_comparison_service.py` — обновление
- `gui/dialog_kp_comparison.py` — обновление с графиками
- `utils/price_normalizer.py` — нормализация цен

**Критерии приёмки:**
- [ ] Таблица заполняется автоматически
- [ ] "Лучшая цена" определяется корректно
- [ ] Есть график сравнения
- [ ] Можно экспортировать в Excel

**Описание:** Расчёт потенциальной экономии при выборе того или иного поставщика.

- Учёт скрытых затрат (подключение, оборудование)
- Сценарии: оптимистичный / реалистичный / пессимистичный
- График ROI

**Техническая реализация:**
- Хранение текущих контрактов и цен
- Алгоритмы прогнозирования

**Файлы:**
- `core/models.py` — таблица `CurrentContracts`
- `services/savings_calculator.py` — калькулятор
- `gui/dialog_savings_forecast.py` — диалог прогноза

#### P12 — REST API

- Эндпоинты: GET/POST/PUT/DELETE для контактов, профилей, КП

#### P13 — OAuth2 (Gmail/Yandex)

**Описание:** Безопасное подключение почты через OAuth2 вместо паролей.

**Функционал:**
- Кнопка "Подключить Gmail" → перенаправление на Google OAuth
- Кнопка "Подключить Яндекс" → перенаправление на Yandex OAuth
- Хранение refresh_token в зашифрованном виде
- Автоматическое обновление access_token

**Техническая реализация:**
- Интеграция с `google-auth`, `yandex-oauth`
- Веб-сервер для callback (localhost:8080)
- Шифрование токенов

**Файлы:**
- `services/oauth_service.py` — сервис OAuth
- `gui/dialog_oauth.py` — диалог подключения

#### P14 — Webhook уведомления

**Описание:** Уведомления о важных событиях в Telegram или на email.

**Функционал:**
- Получено новое КП → уведомление
- Просрочен срок ответа → напоминание
- Ошибка LLM → алерт администратору
- Настройка: какие события, куда отправлять

**Техническая реализация:**
- Интеграция с python-telegram-bot
- Отправка email через SMTP
- Конфигурация webhook URL

**Файлы:**
- `services/notification_service.py` — сервис уведомлений
- `gui/dialog_notifications.py` — настройка

#### P15 — Few-shot learning

**Описание:** Обучение LLM на успешных письмах пользователя для улучшения качества ответов.

**Функционал:**
- Сбор примеров: входящее письмо → идеальный ответ
- Хранение в таблице `training_examples`
- Включение примеров в промпт LLM
- Оценка качества: пользователь ставит ⭐ ответу

---

#### P16 — A/B тестирование промптов

**Описание:** Сравнение разных промптов для выбора лучшего.

**Функционал:**
- Создание 2+ вариантов промпта
- Разделение трафика 50/50
- Метрики: время ответа, точность классификации, оценка пользователя
- Автоматический выбор победителя

---

#### P17 — Автоответы на вопросы

**Описание:** Автоматическая генерация ответов на типовые вопросы поставщиков.

**Функционал:**
- Распознавание вопросов: "Какой объём?", "Сроки?", "Условия оплаты?"
- Генерация ответа из профиля закупки
- Автоотправка (в режиме AUTO)
- Статистика: сколько вопросов обработано автоматически

---

#### P18 — Прогнозирование КП

**Описание:** Предсказание сроков получения КП и ориентировочных цен.

**Функционал:**

- Прогноз цены: "Ожидаемая цена: 15-20 тыс./мес"
- Уведомление: "Поставщик X обычно отвечает с опозданием"
