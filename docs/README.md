## 1. Назначение системы

### 1.1. Общее описание

**Spam KP Assistant** — это автоматизированная система для получения коммерческих предложений (КП) от поставщиков телекоммуникационных услуг. Система предназначена для операторов связи, закупщиков и компаний, регулярно запрашивающих цены на телеком-услуги.

### 1.2. Проблема, которую решает система

При строительстве или расширении сети оператору связи необходимо получить коммерческие предложения от десятков или сотен потенциальных поставщиков. Каждый запрос требует:

- Составления индивидуального письма с описанием требований
- Поиска актуальных контактов поставщиков
- Отправки писем с соблюдением лимитов (чтобы не попасть в спам)
- Регулярной проверки входящих на предмет ответов
- Классификации ответов (КП, спам, вопросы, отказы)
- Создания задач по обработке полученных предложений

**Ручной процесс** занимает от нескольких часов до нескольких дней работы одного сотрудника.

### 1.3. Автоматизация процесса

Система автоматизирует весь цикл работы:

| Этап | Ручной процесс | Автоматизация в системе |
|------|---------------|------------------------|
| **Подготовка** | Составление ТЗ вручную | Мастер создания профиля закупки (5 шагов) |
| **Контакты** | Поиск email на сайтах | Импорт из CSV/XLSX с дедупликацией |
| **Письма** | Написание каждого письма | Шаблоны с переменными, авто-генерация |
| **Отправка** | Ручная отправка по одному | Очередь с задержками, лимиты в час |
| **Приём** | Проверка почты вручную | IMAP проверка по расписанию |
| **Классификация** | Чтение каждого письма | LLM-классификация: КП/спам/вопрос/отказ |
| **Обработка** | Ручной разбор КП | Авто-извлечение цен, сроков, условий |
| **Задачи** | Создание задач вручную | Авто-создание задач оператору |

### 1.4. Целевая аудитория

- **Операторы связи** — компании, строящие или расширяющие сеть
- **Закупщики** — специалисты по закупкам телеком-услуг
- **IT-директора** — принимающие решения о подключении
- **Менеджеры проектов** — координирующие подключение объектов

### 1.5. Типы закупаемых услуг

Система изначально ориентирована на:
- Интернет-каналы (включая выделенные линии)
- Виртуальные АТС и телефонию
- Оптические каналы связи
- Коллокации и размещение оборудования
- VPN и корпоративные сети
- Облачные сервисы и хостинг

#### Проблемы, возникшие при разработке, и их решения

**Проблема 1: Окно не отображалось при запуске**
- **Симптом:** Приложение запускалось, но окно не появлялось
- **Причина:** app.exec() возвращал управление до отрисовки
- **Решение:** Добавлены app.processEvents() и time.sleep(0.5) перед exec()
- **Файл:** run_now.py

**Проблема 2: Метки счётчиков создавались после использования**
- **Симптом:** AttributeError: 'MainWindow' object has no attribute 'lbl_profile_count'
- **Причина:** _load_profiles() вызывался до создания QLabel
- **Решение:** Изменён порядок в _setup_ui() — сначала создание виджетов, потом загрузка данных
- **Файл:** gui/main_window.py

**Проблема 3: Демо-окно блокировало главное окно**
- **Симптом:** Приложение "зависало" при старте
- **Причина:** Модальный диалог (exec()) блокировал event loop
- **Решение:** Сделано не-модальным (setModal(False)), показ через QTimer.singleShot(500, ...)
- **Файл:** gui/main_window.py, gui/dialog_welcome.py

**Проблема 4: Дублирующиеся методы и ошибки импорта**
- **Симптом:** SyntaxError, ImportError
- **Причина:** Неправильные относительные импорты, дублирование кода при слиянии
- **Решение:** Унифицированы импорты, удалены дубликаты, исправлены отступы
- **Файл:** gui/dialog_welcome.py

**Проблема 5: Кнопка "Открыть руководство" не работала**
- **Симптом:** При нажатии ничего не происходило
- **Причина:** Неправильный путь к файлу, отсутствие обработки ошибок
- **Решение:** Создан класс GuideViewer для inline-просмотра, добавлен fallback на os.startfile()
- **Файл:** gui/dialog_welcome.py

**Проблема 6: Кодировка в консоли Windows**
- **Симптом:** UnicodeEncodeError при выводе emoji
- **Причина:** PowerShell по умолчанию использует cp1251
- **Решение:** Заменены emoji на ASCII-эквиваленты в выводе print()
- **Файл:** run_now.py

- **Файл:** services/mailing_service.py

## 3. Архитектура и технологии

### 3.1. Общая архитектура

Система построена по принципу **многоуровневой архитектуры** с чётким разделением ответственности:

```
┌─────────────────────────────────────────────┐
│  Уровень представления (GUI)                │
│  PyQt6, QMainWindow, QDialog, QWidget       │
├─────────────────────────────────────────────┤
│  Уровень бизнес-логики (Services)           │
│  Импорт, SMTP, LLM, Парсеры                 │
├─────────────────────────────────────────────┤
│  Уровень доступа к данным (ORM)             │
│  SQLAlchemy, CRUD операции                  │
├─────────────────────────────────────────────┤
│  Уровень данных (Database)                  │
│  SQLite, файловая система                   │
└─────────────────────────────────────────────┘
```

- **SQLAlchemy 2.x** — выбрана за счёт:
  - Декларативного стиля определения моделей
  - Мощной системы запросов
  - Поддержки миграций (через Alembic, при необходимости)
  - Интеграции с PyQt6 (модели данных)

#### Шифрование
- **cryptography (Fernet)** — выбрано за счёт:
  - Простоты использования (высокоуровневый API)
  - Безопасности (AES-128 в режиме CBC)
  - Автоматической аутентификации сообщений (HMAC)

#### Логирование
- **loguru** — выбрано за счёт:
  - Простоты настройки (одна строка)
  - Автоматической ротации
  - Форматирования с цветами
  - Асинхронной записи

#### Тестирование
- **pytest** — выбран за счёт:
  - Простоты написания тестов
  - Фикстур
  - Параметризации
  - Хороших отчётов

#### LLM API
- **ProxyAPI** — выбран за счёт:
  - Доступа к GPT-4o, GPT-4o-mini, Gemini
  - Российских карт оплаты
  - Простого API (OpenAI-совместимого)
  - Низких цен

### 3.3. Принципы проектирования

1. **KISS (Keep It Simple, Stupid)** — простые решения предпочтительнее сложных
2. **DRY (Don't Repeat Yourself)** — переиспользование кода через утилиты
3. **Separation of Concerns** — чёткое разделение GUI, бизнес-логики и данных
4. **Fail Fast** — ранняя валидация и обработка ошибок
5. **Security by Design** — шифрование паролей изначально

### 4.4. SMTP/IMAP менеджер

#### Описание
Менеджер email-аккаунтов отвечает за:
- Отправку писем через SMTP
- Получение писем через IMAP
- Хранение учётных данных в зашифрованном виде

#### Поддерживаемые провайдеры

| Провайдер | SMTP сервер | Порт | IMAP сервер | Порт |

| Yandex | smtp.yandex.ru | 465 | imap.yandex.ru | 993 |
| Mail.ru | smtp.mail.ru | 465 | imap.mail.ru | 993 |
| Другой | Ручной ввод | Ручной | Ручной ввод | Ручной |

#### Безопасность

- Пароли хранятся в зашифрованном виде (Fernet)
- Шифрование применяется перед сохранением в БД
- Дешифрование происходит непосредственно перед использованием
- Ключ шифрования генерируется при первом запуске
- Рекомендуется использование App Password (Gmail, Yandex)

#### Настройка аккаунта

1. Выбор провайдера из списка
2. Автозаполнение серверов (для известных)
3. Ввод email
4. Ввод пароля (маскированное поле)
5. Проверка подключения (тестовое письмо)
6. Назначение основного аккаунта (опционально)

## 7. Безопасность

### 7.1. Шифрование паролей

#### Алгоритм
- **Fernet** из библиотеки cryptography
- Симметричное шифрование (AES-128 в режиме CBC)
- Аутентификация сообщений (HMAC-SHA256)

#### Генерация ключа
```python
from cryptography.fernet import Fernet
key = Fernet.generate_key()  # 32 байта, base64-encoded
```

#### Шифрование
```python
cipher = Fernet(key)
encrypted = cipher.encrypt(password.encode('utf-8'))
# Сохраняем encrypted в БД
```

#### Дешифрование
```python
cipher = Fernet(key)
decrypted = cipher.decrypt(encrypted).decode('utf-8')
# Используем decrypted для SMTP/IMAP
```

#### Хранение ключа
- Ключ хранится в файле (не в БД)
- Файл ключа: data/.key (или аналогичный)
- Рекомендуется ограничить права доступа к файлу

### 7.2. Защита документации

#### Механизм
- Руководство хранится в docs/USER_GUIDE.md
- Резервная копия: data/backup_guide.md
- Проверка при каждом запуске (utils/file_protection.py)

#### Логика
```
1. Проверить существование файла
2. Если существует:
   - Сравнить с резервной копией
   - Если изменился — обновить резервную копию
3. Если не существует:
   - Попытаться восстановить из backup_guide.md
   - Если backup нет — создать минимальную версию
```

### 7.3. Рекомендации по безопасности

1. **App Password:** Используйте App Password вместо основного пароля (Gmail, Yandex)
2. **Двухфакторная аутентификация:** Включите 2FA на email-аккаунтах
3. **Резервное копирование:** Регулярно копируйте data/spam_kp_assistant.db
4. **Антивирус:** Убедитесь, что антивирус не блокирует приложение
5. **Права доступа:** Ограничьте доступ к папке data/

## 13. Известные проблемы и ограничения

### 13.1. Текущие проблемы

#### Проблема 1: GUI отображение в некоторых средах

**Описание:** В некоторых терминалах (особенно VS Code Terminal) окно приложения может не появляться или появляться и сразу закрываться.

**Причина:** Конфликт event loop PyQt6 с event loop терминала.

**Обходное решение:**
- Использовать `pythonw.exe` вместо `python.exe`
- Запускать через .bat файл
- Запускать из обычного cmd (не VS Code Terminal)

**Статус:** Известная проблема, есть обходное решение

#### Проблема 2: Кодировка в консоли Windows

**Описание:** При запуске через PowerShell некоторые символы Unicode (emoji, стрелки) отображаются как знаки вопроса или вызывают UnicodeEncodeError.

**Причина:** PowerShell по умолчанию использует кодировку cp1251, которая не поддерживает все Unicode-символы.

**Обходное решение:**
- Использовать Windows Terminal (поддерживает UTF-8)
- Использовать Git Bash
- Запускать из IDE (PyCharm, VS Code)

**Статус:** Известная проблема, есть обходное решение

#### Проблема 3: Отсутствие пакета email-validator

**Описание:** Тесты test_import.py падают с ошибкой импорта email_validator.

**Причина:** Пакет не включён в requirements.txt.

**Решение:**
```bash
pip install email-validator
```

**Статус:** Некритично, валидация работает через regex

#### Проблема 4: Размер окна на маленьких экранах

**Описание:** На экранах с разрешением менее 1366x768 окно может не помещаться.

**Причина:** Фиксированный минимальный размер окна.

**Обходное решение:**
- Изменить масштабирование Windows (125% → 100%)
- Использовать режим планшета

**Статус:** Будет исправлено в v1.1

## 17. Часто задаваемые вопросы

### Q: Почему приложение называется "Спам-КП"?
**A:** "Спам" здесь в значении "массовая рассылка", не в негативном смысле. Система отправляет персонализированные письма с запросом КП.

### Q: Можно ли использовать без ProxyAPI?
**A:** Да, для Этапов 1-3 LLM не требуется. Для Этапа 4 нужен API ключ.

### Q: Где хранятся пароли?
**A:** Пароли шифруются (Fernet) и хранятся в локальной SQLite. Ключ шифрования хранится отдельно.

### Q: Можно ли импортировать контакты из Excel?
**A:** Да, поддерживаются CSV и XLSX.

### Q: Сколько контактов можно импортировать?
**A:** Теоретически — неограниченно. Практически — tested до 10,000.

### Q: Работает ли на Linux/Mac?
**A:** Код кроссплатформенный, но тестировалось только на Windows.

### Q: Как обновить приложение?
**A:** Скопируйте новые файлы поверх старых. База данных сохранится.

### Q: Где посмотреть логи?
**A:** Файл `data/app.log` или через меню Справка → Логи.

### Q: Что делать, если окно не появляется?
**A:** Используйте `pythonw.exe` или запустите через .bat файл.
